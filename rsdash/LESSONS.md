# บทเรียนและข้อปรับปรุง — RS Dashboard (THUSHOUSE)

สรุปจากงานช่วง 5–6 พฤศจิกายน 2026 (RS ทุก TF, Pivot Break VDU/VCP, ค้นหาหุ้น, ป้ายงบ, แปลคำอธิบายบริษัท)

## 1) สิ่งที่ทำเสร็จและใช้งานจริงแล้ว

- เปลี่ยนนิยาม RS: 3M/6M = เปอร์เซ็นไทล์ของผลตอบแทนช่วงนั้นตรง ๆ · 1Y = ถ่วง 1 เดือน 30% · 3 เดือน 30% · 6 เดือน 20% · 1 ปี 20% คำนวณย้อนหลังใหม่ทั้งไทย (872 ตัว) และสหรัฐ (2,383–2,517 ตัว)
- หน้า How to และ tooltip ปุ่ม 3M/6M/1Y อธิบายนิยามใหม่ตรงกัน
- Pivot Break (VDU/VCP) ในหน้า Scanner: ตารางแยก 4 กลุ่ม (เบรกแล้ว/รอเบรก × VDU/VCP) มีโลโก้ ชื่อหุ้น จุดข่าว/SSF/DR/งบ คอลัมน์ % ถึง pivot และปุ่มดูการ์ดกราฟต่อกลุ่ม
- เกณฑ์ผ่าน Wait ก่อนสแกน: ปิด > SMA150 และ SMA50 > SMA200 และหน้าเว็บกรอง RS > 60 ตามฐานที่เลือก
- กราฟโชว์รายละเอียด Pivot Break: เส้น pivot สั้นจากแท่งยอดถึงแท่งเบรก (ทึบ บาง ไม่มีป้าย) จุด VDU ย้อนหลังเฉพาะที่เบรกได้ จุดเบรกพร้อมตัวเลขปริมาณ เช่น 3.82x และจุดย่อ VCP พร้อม %
- เบรกราคาสดระหว่างวัน: ขึ้นกลุ่มเบรกแล้วทันทีพร้อมป้าย Pre และป้ายจะหายเองเมื่อรอบปิดตลาดยืนยันด้วยแท่งจริง
- ป้ายงบทั้งเว็บเหลือจุดเดียว: จุดทอง = ใกล้ออก/ออกวันนี้ · จุดเทา = ประกาศแล้ว · รายละเอียดเต็มอยู่ในป็อปอัป
- ช่องค้นหาหุ้นช่องเดียวในหัวเว็บ ใช้ได้ทุกหน้า และพิมพ์ในหน้า "หุ้น" จะกรองตารางจริง
- แปลคำอธิบายบริษัทเป็นแบบกดปุ่ม "แปล" (ไม่แปลอัตโนมัติ) และ API อ่านไฟล์แปลล่วงหน้าก่อน
- งานอัตโนมัติ: cron 17:10 จันทร์–ศุกร์ สแกน Pivot Break ใหม่หลังตลาดไทยปิดแล้ว deploy ทันที · pipeline 18:15 ก็มีสแกนซ้ำเผื่อพลาด

## 2) ปัญหาที่เจอและต้นเหตุจริง

- BGRIM หายจาก Break VDU: ตัวสแกนฝั่งไทยอ่านแท่งล่าสุดจาก TradingView ซึ่งแท่งยังไม่นิ่ง ทำให้เงื่อนไข "ปิดเหนือ SMA50 ของแท่งแห้ง" เปลี่ยน → แก้เป็นอ่าน Yahoo ก่อน (แหล่งเดียวกับหน้าเว็บ) และเพิ่มสถานะ "รอ Vol" ไม่ให้หุ้นหายเงียบ
- จุด VDU ล่าสุดหายจากกราฟ: ประวัติ VDU ตัดช่วงก่อนแท่งล่าสุด 11 แท่ง → รวม `vduDate` ของแถวนั้นเข้าไปในชุดจุด
- ค้นหาหุ้นพิมพ์แล้วไม่ขึ้น: บล็อกโค้ดค้นหาถูกลบตอนเขียนทับช่วง `pvApplyMarks` → ใส่กลับและผูกกับการกรองลิสต์หน้า "หุ้น"
- กดดูการ์ดกราฟแล้วกราฟไม่ขึ้น: ลบ `<span class="ern-wrap">` ด้วย regex แล้วกัดบล็อก `const SURP`/`surpLoad` หายไป → `ReferenceError: SURP is not defined` ทำให้วาดการ์ดทั้งชุดล้ม
- จุดงบซ้ำ 2 จุดต่อแถว: จุดมาจาก `tkT` อยู่แล้ว แล้วยังมีป้ายงบเดิมต่อท้ายอีกชั้น → ซ่อนด้วย CSS เฉพาะในลิสต์ ไม่แตะป็อปอัป
- เส้น pivot ยาวทั้งกราฟ: ใช้ price line ของไลบรารีซึ่งลากเต็มช่วง → เปลี่ยนเป็น line series 2 จุด
- Marker ถูกทับหาย: `bsApplyMarks` เป็น async และเขียนทับ marker ภายหลัง → ต้องรอ `.then()` ก่อนเติม overlay
- ตัวแปรไม่แชร์ข้าม handler: `let` ระดับบล็อกไม่เห็นจาก handler อื่น → ใช้ `window.*` สำหรับสถานะที่ต้องใช้ข้ามฟังก์ชัน
- ตารางแคบผิดปกติ: `pvToggle` ตั้ง `display:flex` ทับ ทำให้ลูกถูกบีบ → ใช้ `block`
- ตัวเลขบนเว็บไม่ตรงไฟล์: ค่าบางจุดคำนวณสดจากอีกแหล่ง → ยึดแหล่งเดียว (`/api/scan` + ไฟล์ปิดตลาด)

## 3) ข้อปรับปรุงกระบวนการ (กันวนแก้ไปพังไป)

1. ห้ามลบหรือแทนโค้ดด้วย regex หลายจุดในครั้งเดียว — ให้แทนทั้งบล็อกด้วยสตริงเต็ม หรือแก้ทีละจุด แล้ว `node --check` ทุกไฟล์สคริปต์หลังแก้ทันที
2. ก่อนแก้ ให้ระบุ "ช่วงโค้ดที่ถือว่าเป็นเจ้าของ" (เช่น บล็อกของ Claude กับของ Hermes) และห้ามเขียนทับข้ามช่วง
3. ทุกครั้งที่แตะ `index.html` ต้องมี三道 ตรวจ: syntax ทุก `<script>`, โหลดเว็บจริง, และกดใช้งานจริงอย่างน้อยหนึ่งเส้นทาง (การ์ดกราฟ/ป๊อปอัป/ค้นหา)
4. เก็บ baseline ไฟล์ก่อนแก้ (git commit ทุกครั้ง) เพื่อย้อนได้ในคำสั่งเดียว — รอบนี้รอดเพราะย้อนไป `HEAD~1`
5. แก้เรื่องข้อมูล (สแกน/RS) ให้ยึดแหล่งเดียว และเพิ่มสถานะ fallback (เช่น รอ Vol) แทนการปล่อยให้แถวหาย
6. งานที่กระทบทั้งเว็บ (ป้ายงบ/จุด/ไอคอน) ให้ทำผ่าน CSS หรือฟังก์ชันกลาง ไม่กระจายแก้ตามเทมเพลตหลายสิบจุด
7. ก่อน deploy ให้ตรวจว่า API หลักตอบ 200 และจำนวนแถวไม่ลดผิดปกติ และตรวจซ้ำหลัง deploy ด้วยเบราว์เซอร์จริง
8. งานที่มีผลกับตัวเลขผู้ใช้ (RS/อันดับ/สัญญาณ) ต้องรันใหม่ทั้งตลาดและบันทึกผลก่อน–หลังไว้ใน HANDOFF

## 4) งานที่ยังค้าง

- VCP ยังไม่ตรงนิยาม: รอเคาะ 3 ข้อ (จำนวนรอบย่อ · ความตื้นรอบสุดท้าย · ยอดฐานที่ใช้เป็น pivot) ก่อนเขียนตัวสแกนใหม่แยกไฟล์และเทียบผลกับของเดิม
- ไฟล์แปลคำอธิบายบริษัท: กูเกิลยังบล็อก IP เครื่องนี้ชั่วคราว ตั้งคิวกลางคืน 22:30 ไว้ค่อย ๆ แปลและ deploy เมื่อมีของใหม่
- ยังไม่ได้ push ขึ้น origin (ตามกติกา รอเจ้าของสั่ง)

# วิธีวิจัยแบบเข้มงวด (rsdash / Port Champ)

เป้าหมาย: ตอบว่า "กลยุทธ์นี้มี edge จริงไหม" โดยไม่หลอกตัวเอง ผลลบที่รายงานตรง ๆ มีค่าเท่ากับผลบวก
ผู้ใช้ชอบให้ **ถามละเอียด (10–30 ข้อ) ก่อนทดสอบ** และให้ **บันทึกทุกอย่างลง git/โฟลเดอร์** ผลลัพธ์ต้องเป็นข้อเท็จจริง ไม่ปั้นให้ดูดี

## ขั้นตอน (ห้ามข้าม ห้ามสลับลำดับ)

1. **Grill ก่อน** ถามผู้ใช้ให้ครบ: ตลาด/ช่วงเวลา, จำนวนหุ้น, น้ำหนัก, ต้นทุน, ตัวเทียบ, Gate, เกณฑ์ผ่าน, ข้อมูลที่ต้องดึงเพิ่ม (ขออนุญาตก่อนดึง)
2. **เขียน PREREG แล้ว commit ก่อนรันสคริปต์ใด ๆ** ใช้ `node scripts/prereg.mjs new <slug>` สร้างจากเทมเพลต ([references/PREREG_template.md](references/PREREG_template.md)) แล้วกรอกให้ครบ ห้ามแก้เกณฑ์หลังเห็นผล
3. **เขียน/รันสคริปต์** ตามกฎ PREREG เท่านั้น (ดู "กฎกันผลหลอก" ด้านล่าง) เก็บผลดิบเป็น JSON ใน `data/`
4. **เขียน REPORT** ตามเทมเพลต ([references/REPORT_template.md](references/REPORT_template.md)): ตารางผล, ผ่าน/ไม่ผ่านเทียบเกณฑ์ที่ล็อก, ข้อจำกัด, ขั้นต่อไป
5. **ตรวจ** `node scripts/prereg.mjs check` (PREREG ต้องถูก commit ก่อน REPORT/ผลลัพธ์) แล้ว commit
6. **ถ้าผ่านทุกเกณฑ์** ยังเรียกได้แค่ "มีหลักฐานเบื้องต้น" ต้อง forward paper-trade ≥ 36 เดือน (t-stat ≥ 2) ก่อนเรียกว่า edge
7. **ถ้าไม่ผ่าน** เขียนว่า "ไม่พบ edge" ตรง ๆ อย่าไล่ปรับพารามิเตอร์จนผ่าน ถ้าจะสำรวจเพิ่มต้องทำ PREREG ฉบับใหม่ และนับเป็น multiple testing

## กฎกันผลหลอก (ต้องทำทุกครั้ง)

- **ไม่มี look-ahead:** สัญญาณคำนวณจากข้อมูลปิดวัน k ซื้อขายที่ราคาเปิดวัน k+1 เป็นอย่างน้อย; ตัวชี้วัดที่ใช้ high/low 52 สัปดาห์ต้องไม่รวมวันที่ยังไม่เกิด
- **ต้นทุนจริงต่อตลาด** (ไทย 0.35%/ข้าง, US 0.207%/ข้าง ตามที่ผู้ใช้กำหนด) + ดอกเบี้ยเงินสด (T-Bill/FRED DTB3 สำหรับ US) + ตัวเทียบแบบ total return
- **กลุ่มควบคุมสุ่ม:** เลือกหุ้นสุ่มจำนวนเท่ากัน จากพูลเดียวกัน ต้นทุน/ความถี่เท่ากัน 500 seeds แยก 2 พูล (พูลกรอง และพูลกว้าง) เกณฑ์ปกติ ≥ 499/500 ชนะสุ่ม
- **Out-of-sample / แบ่งช่วง:** ต้องผ่านทั้งช่วงแรกและช่วงหลัง (เช่น 2015–19 และ 2020–ปัจจุบัน) และเลื่อน 3 ปี rolling; กำไรที่มาจากช่วงเดียว = ไม่ผ่าน
- **Multiple-testing penalty:** นับจำนวนชุดที่ทดสอบ; ผลที่เป็น "ดีที่สุดจากหลายชุด" ต้องหักความเชื่อมั่น ผลสำรวจ (EXPLORE) ไม่ใช่การพิสูจน์
- **Cross-market replication:** edge ที่เห็นในตลาดหนึ่ง ต้องลองกับตลาดอื่นที่ไม่เคยใช้หากฎ (ผ่านอย่างน้อย 3 จาก 4 ตลาดจึงเรียกว่ายืนยันเบื้องต้น)
- **Survivorship:** ถ้าไม่มีหุ้นที่ถูกเพิกถอน ให้ระบุและหักค่าประมาณ (haircut) ห้ามละเว้น; ไทย/EM ปัจจุบันยังไม่มีข้อมูล delisted
- **ความไว (sensitivity):** ลองเลื่อนวันเข้า 1–5 วัน, ปรับต้นทุน ×2, ตัด 5 ตัวที่กำไรสูงสุด ถ้าผลพังเมื่อตัด = พึ่งหุ้นไม่กี่ตัว
- **นิยามเดียวกันทั้งเว็บและ backtest:** ตัวชี้วัดที่ใช้ในหน้าเว็บ (เช่น ATR10/ATR50) ต้องคำนวณแบบเดียวกับที่ทดสอบ แยกไว้ใน `rsdash/*.js` แบบ UMD แล้วเขียนเทสต์ใน `tests/`
- **ข้อมูลพื้นฐาน (EPS ฯลฯ) ต้อง point-in-time:** ห้ามใช้ค่าปัจจุบันย้อนหลัง; ใช้ log จาก `fund|th|log|YYYY-MM` ใน Supabase ที่เก็บวันที่ค่าเปลี่ยนจริง

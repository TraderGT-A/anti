# US Top20 News Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ดึงข่าวฟรีรายวันของหุ้น US ที่ติด Top20 (YTD ∪ RS) ลง md รายตัวใน vault และโชว์สรุปในหน้า Top20 ของ rsdash

**Architecture:** สคริปต์ Node (`scripts/news/*.mjs`, ไม่มี dependency) รันด้วย Windows Task Scheduler: หา universe จาก rsdash API → ดึง RSS/JSON ฟรี → dedupe ด้วย state → ต่อท้าย md → upsert แถวสั้นลง Supabase `stock_notes` → rsdash อ่านผ่าน `/api/notes`. ส่วน "ทำไมติด Top20" และ "มุมมองจาก X" Claude เขียนเมื่อผู้ใช้สั่ง แล้วใช้ `--summary-only` push ขึ้น

**Tech Stack:** Node 24 (built-in `fetch`, `node:test`, `process.loadEnvFile`), Supabase PostgREST, Vercel serverless, vanilla JS ใน `rsdash/index.html`

**Spec:** `docs/superpowers/specs/2026-10-12-us-top20-news-design.md`
(เปลี่ยนจาก spec: Python → Node `.mjs` เพราะเครื่องนี้ไม่มี Python ใน PATH และเทสต์ทั้ง repo ใช้ `node:test` — Task 1 แก้ spec ให้ตรง)

## Global Constraints
- ค่าใช้จ่าย $0: ห้ามเรียก API ที่เสียเงิน (X API, Claude API, xAI)
- ไม่มี npm dependency ใหม่ในสคริปต์ข่าว (ใช้ built-in ของ Node 24 เท่านั้น)
- universe: `GET https://rsdashclean.vercel.app/api/scan?market=america&universe=all&v=2` → Top20 ตาม `pYTD` ∪ Top20 ตาม `score`
- แหล่ง: Yahoo `https://feeds.finance.yahoo.com/rss/2.0/headline?s={T}&region=US&lang=en-US`, Google News `https://news.google.com/rss/search?q=%22{T}%22+stock+when:7d&hl=en-US&gl=US&ceid=US:en`, SEC `https://data.sec.gov/submissions/CIK{10 หลัก}.json` + map `https://www.sec.gov/files/company_tickers.json`, Reddit `https://www.reddit.com/r/{sub}/search.json?q={T}&restrict_sr=1&sort=new&t=week&limit=25` สำหรับ sub ∈ `stocks, wallstreetbets, investing`
- SEC ต้องมี User-Agent พร้อมช่องทางติดต่อ: อ่านจาก env `NEWS_SEC_UA` ที่ผู้ใช้ตั้งเอง; ไม่มี → ข้าม SEC และ log (ห้ามใส่อีเมลผู้ใช้ลงโค้ด)
- SEC forms ที่เก็บ: `8-K, 10-Q, 10-K, 4`
- หน่วง ≥1000 ms ระหว่าง request ไปโดเมนเดียวกัน
- ย้อนหลังรอบแรก/ตัวที่เพิ่งเข้า: 30 วัน; rsdash แสดงหัวข่าว 5 อัน; นับข่าว 7 วัน
- md: `Stocks_US/<FILE>.md` ที่ root ของ vault; หัวข้อคงที่: `## ทำไมติด Top20`, `## มุมมองจาก X`, `## Feed`
- ไฟล์ลับ/สถานะไม่เข้า git: `scripts/news/.env`, `data/news_state.json`, `data/news_log.txt`
- แก้ `rsdash/` แล้วต้องคัดลอกไฟล์เดียวกันไป `rsdash/rsdash_clean_deploy/` ให้เหมือนกันทุกไบต์ (ตามแบบ commit d89abbe)
- ข้อความบนหน้า/ไฟล์: "อธิบายย้อนหลัง ไม่ใช่การพิสูจน์สาเหตุ / ไม่ใช่สัญญาณซื้อขาย"
- การกระทำที่ต้องขออนุมัติผู้ใช้ก่อน: สร้างตาราง Supabase, สร้าง Task Scheduler job, `vercel --prod` (เช็ก `vercel whoami` ก่อน)

### Task 3: Store (dedupe, state, membership, md)

**Files:**
- Create: `scripts/news/store.mjs`
- Test: `tests/news_store.test.mjs`
- Modify: `.gitignore` (+ `scripts/news/.env`, `data/news_state.json`, `data/news_log.txt`)

**Interfaces:**
- Consumes: `Item` (Task 2), universe entry (Task 1)
- Produces:
  - `State = { v: 1, lastRun: 'YYYY-MM-DD'|null, seen: { [key]: 'YYYY-MM-DD' }, members: { [ticker]: { name, since, lists, left? } }, recent: { [ticker]: Item[] } }`
  - `itemKey(item) -> string` (sha1 ของ url ตัด query `utm_*` และ `#`) · `normTitle(title) -> string` (lowercase, ตัดเครื่องหมาย/ช่องว่างซ้ำ)
  - `dedupe(items, state) -> Item[]` (ตัดที่ key อยู่ใน `state.seen` หรือ normTitle ซ้ำกันภายในชุด/ใน `state.recent[ticker]`; เพิ่ม key ที่ผ่านลง `state.seen`)
  - `loadState(path) -> State` (ไม่มีไฟล์ → state ว่าง) · `saveState(path, state)` (เขียนไฟล์ชั่วคราวแล้ว rename)
  - `updateMembership(state, universe, today) -> { entered: string[], left: string[] }` (เข้าใหม่หรือกลับเข้า → `since = today`, ลบ `left`; หลุด → `left = today`)
  - `sinceFor(state, ticker, today) -> 'YYYY-MM-DD'` (เพิ่งเข้า/ไม่มี lastRun → today−30 วัน; ไม่งั้น `state.lastRun`)
  - `pruneRecent(state, today)` (เก็บ `recent` แค่ 30 วัน, `seen` แค่ 120 วัน)
  - `fileNameFor(ticker) -> string` (`BRK.B` → `BRK-B.md`)
  - `renderFeedBlock(date, items) -> string` (`### {date}` + บรรทัด `- [Yahoo] title ([ลิงก์](url))`; reddit: `[Reddit r/{sub} ▲{score}]`; sec: `[SEC {form}]`)
  - `upsertStockMd(existing: string|null, meta: { ticker, name, lists, since, left?, lastFetch }, block: string|null) -> string`
  - `renderIndexMd(state, today) -> string` (ตาราง: `[[FILE]]`, ชื่อ, lists, since, ข่าว 7 วัน, Reddit 7 วัน; สมาชิกที่ `left` อยู่ตารางแยก "หลุดแล้ว"; บรรทัด `last_fetch`)

`upsertStockMd` กติกา (ตัดสินใจไว้ตรงนี้):
- existing เป็น null → สร้างจากแม่แบบใน spec ข้อ 4 (frontmatter + `# {ticker} — {name}` + 3 หัวข้อ; ใต้ "ทำไมติด Top20" ใส่ `_ยังไม่มีสรุป — สั่ง "สรุป Top20 US"_`)
- มีอยู่แล้ว → แทนที่เฉพาะ frontmatter; ทุกอย่างก่อน `## Feed` คงเดิมทุกไบต์
- block ใหม่แทรกใต้บรรทัด `## Feed` ทันที (ใหม่สุดบน); ถ้ามี `### {date}` วันเดียวกันอยู่แล้ว → รวมบรรทัดใหม่เข้า heading เดิม (ไม่สร้างซ้ำ)
